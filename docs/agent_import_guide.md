# Agent 导入新 LOF 执行手册

本文档面向后续执行导入任务的 agent。目标不是追求一次全自动导入，而是保证每只 LOF 的数据来源、代理判断、回测结果和已知问题都可审计、可复现。

详细代理原则见 [LOF 估值代理规则](lof_proxy_rules.md)。本手册侧重执行步骤和排错经验。

## 工作目标

导入一只新 LOF 时，最终要完成：

1. 确认它是真正有场内交易价格的 LOF。
2. 拉取基金历史净值、分红、场内价格、公告链接。
3. 核验最近几期原始定期报告。
4. 形成可取价的结构化持仓或代理篮子。
5. 写入 `config/fund_rules.json`。
6. 跑单只导入和回测。
7. 判断误差是否可接受。
8. 更新文档中的重要规则或例外。

## 关键文件

| 文件 | 用途 |
|---|---|
| `config/fund_rules.json` | 每只基金的交易市场、代理规则、人工持仓、公告依据 |
| `import_fund.py` | 单只基金导入入口 |
| `build.py` | 全量构建入口，导入多只基金时较慢 |
| `refresh_announcements.py` | 只刷新最新公告链接 |
| `app/config.py` | 基金规则加载、汇率映射、Yahoo 代理符号映射 |
| `app/build.py` | 导入净值、公告、持仓、行情和回测的主逻辑 |
| `app/sources.py` | 东方财富、Yahoo 等数据源请求和解析 |
| `app/valuation.py` | 日内估值、回测、持仓可用日切换、汇率合成 |
| `data/lof_inav.sqlite3` | 本地缓存数据库 |
| `docs/lof_proxy_rules.md` | 代理规则和分类经验 |

## 常用命令

单只导入或刷新：

```powershell
python import_fund.py 160924
```

输出会包含：

```text
backtest: MAE、误差标准差、最大误差、最新误差
latest holdings: 当前最新持仓或代理
largest errors: 最大误差日期
```

全量构建：

```powershell
python build.py
```

全量构建会刷新所有配置基金的净值、持仓、行情和回测。基金数量变多后可能较慢，新增单只基金时优先用 `import_fund.py`。

只刷新公告链接：

```powershell
python refresh_announcements.py
```

启动网站：

```powershell
python serve.py
```

访问：

```text
http://127.0.0.1:8001
```

如果修改了 `config/fund_rules.json`，需要重启服务，因为 `FUNDS` 在模块导入时加载。

## 导入流程

### 0. 控制导入节奏

不要一次性导入太多 LOF。之前批量加入多只基金时，同时暴露了几类问题：

```text
非 LOF 混入主列表
场内价格为空
平台持仓展示为空或口径错误
公告发布日期未按实际发布日期切换
代理规则还没核验就进入网页展示
某些新增代理没有实时行情或历史日线
多个基金同时误差偏大，难以判断是行情源、汇率、持仓还是时点问题
```

推荐节奏：

1. 标准指数型可以每批 2-3 只，但仍要逐只跑 `python import_fund.py <code>`。
2. QDII、FOF、商品、ETF 联接、主动基金一次只处理 1 只。
3. 每只基金完成“原始公告核验、配置、导入、回测、网站检查”后，再导入下一只。
4. 不要先把一批基金都放进网站列表再回头修规则。网站展示应只包含已经能解释估值口径的基金。

每只基金进入主列表前，至少确认：

```text
有场内价格
最新公告链接存在
最新持仓或代理不为空
covered_weight 合理
missing_quotes 为空或能解释
MAE、标准差、最大误差已记录
note 不含临时占位描述
```

如果一批导入后出现多个问题，按下面顺序回退到可控状态：

1. 先移出或禁用确认不是 LOF、没有场内价格的基金。
2. 再处理 `missing_quotes`，补 Yahoo 映射或替换代理。
3. 再查原始公告修正持仓和 `publish_date`。
4. 最后才比较 MAE 和选择更细代理。

### 1. 确认是否为场内 LOF

先确认基金有可交易的场内代码和场内价格。不要只看基金名称里是否有 QDII、指数、LOF 字样。

检查点：

1. 东方财富基金页是否能拿到场内价格。
2. `exchange_market` 是深市 `0` 还是沪市 `1`。
3. 是否存在类似 `0.基金代码` 或 `1.基金代码` 的实时行情。

反例：

```text
160213 国泰纳斯达克100指数 QDII
它是场外基金，不是 LOF 主列表对象，不能纳入需要场内折溢价的列表。
```

### 2. 拉基础数据

先在 `config/fund_rules.json` 加入最小配置，再跑：

```powershell
python import_fund.py <code>
```

最小配置示例：

```json
{
  "160924": {
    "exchange_market": 0,
    "proxy_secids": ["100.HSI"],
    "proxy_basis": "stock_gap",
    "manual_holdings_mode": "proxy_only",
    "note": "按股票仓位映射恒生指数代理"
  }
}
```

如果是复杂 QDII、FOF、商品、ETF 联接，不能停留在最小配置，必须继续核验原始公告。

`proxy_basis` 口径：

- `stock_gap`：适合普通指数型 LOF，资产配置中的股票仓位可直接代表指数敞口。
- `non_cash_gap`：适合 ETF 联接或平台资产配置主要显示为“基金投资”的指数产品；用非现金仓位映射目标 ETF 的跟踪指数，避免股票仓位为 0 时丢失实际指数敞口。

### 3. 查原始公告

公告优先级：

1. 基金公司官网或交易所/指定披露平台 PDF。
2. 东方财富公告接口返回的定期报告公告。
3. 东方财富 F10 页面只作为入口，不作为最终事实源。

需要查的报告：

```text
最近 4 期季报：2025Q2、2025Q3、2025Q4、2026Q1 等
必要时补半年报/年报，因为半年报、年报可能披露完整持仓
```

重点查表：

| 表 | 作用 |
|---|---|
| 基金资产组合情况 | 股票、基金、债券、现金、其他资产占总资产比例 |
| 国家/地区分布 | QDII 地区暴露 |
| 行业分类 | 行业基金的代理依据 |
| 股票及存托凭证投资明细 | 股票型或指数型 QDII 的主要资产 |
| 基金投资明细 | FOF、黄金、原油、印度基金等最关键 |
| 金融衍生品投资明细 | 期货、远期、期权等 |
| 其他资产构成 | 大额应收申购款会影响覆盖率 |

注意口径：

```text
估值权重优先用“占基金资产净值比例”
不要把“占基金总资产比例”直接当估值权重
```

### 4. 下载和保存原始公告

原始 PDF 和抽取文本建议保存到 `data/`：

```text
data/<code>_2026q1.pdf
data/<code>_2026q1.txt
```

东方财富公告 ID 可从接口取。PowerShell 不支持 bash 风格 heredoc，应使用 here-string：

```powershell
@'
import requests
code = "160719"
r = requests.get(
    "https://api.fund.eastmoney.com/f10/JJGG",
    params={"fundcode": code, "pageIndex": 1, "pageSize": 20, "type": 3},
    headers={"Referer": f"https://fundf10.eastmoney.com/jjgg_{code}_3.html", "User-Agent": "Mozilla/5.0"},
    timeout=20,
)
for item in r.json().get("Data") or []:
    print(item.get("PUBLISHDATEDesc"), item.get("TITLE"), item.get("ID"))
'@ | python -
```

东方财富 PDF 可能返回反爬脚本，而不是 PDF。判断方式：

```text
PDF 正常开头是 %PDF
如果响应开头是 <script>，说明需要处理 Cookie 或换来源
```

已验证过一种处理方式：解析脚本生成 `__tst_status` 和 `EO_Bot_Ssid` 后重试。若脚本变化，不要硬编码旧 Cookie；重新读取响应脚本并计算。

### 5. 选择代理类型

先判断基金属于哪一类。

#### 指数型 LOF

指数型 LOF 直接使用基金跟踪指数。ETF 联接本质上也按同一原则处理：先找到目标 ETF，再使用目标 ETF 的跟踪指数作为代理，而不是用 ETF 场内价格替代底层净值。

例子：

```text
160924 大成恒生指数 -> HSI
160717 嘉实H股指数 -> HSCEI
161125 易方达标普500 -> SPX
```

如果只披露部分股票持仓，缺口按：

```text
缺口权重 = 股票占净比 - 已披露股票权重
```

补缺口时的指数选择依据：

1. 基金明确跟踪指数时，用跟踪指数。
2. ETF 联接先穿到目标 ETF，再用目标 ETF 的跟踪指数。
3. 主动型没有明确跟踪指数时，优先看业绩比较基准，并按基准指数和权重补足前十大披露之外的股票仓位缺口。
4. 只有业绩比较基准没有可用指数、或基准明显不能解释当前披露持仓时，才按基金名称、投资范围、前十大持仓行业和地区判断市场/风格指数。
5. 不为了降低回测误差选择不符合投资目标的指数。

例子：

```text
161128 已披露美股科技股约 66.95%
股票占净比约 87.52%
缺口约 20.57%
基金风格是美股科技，因此用纳斯达克100补足
```

#### ETF 联接

路径：

```text
联接基金 -> 目标 ETF -> 跟踪指数
```

例子：

```text
501301 持有 520560
520560 跟踪恒生中国(香港上市)30指数
代理用 124.HSFML25，而不是 520560 场内价格
配置使用目标指数 secid；若资产配置主要是基金投资，`proxy_basis` 用 `non_cash_gap`。
```

#### 行业股票基金

如果是行业指数或行业主题基金，优先用行业指数或行业 ETF 代理，不要直接用商品价格替代股票。

例子：

```text
160416 华安标普全球石油
持仓是 Exxon、Chevron、Shell、TotalEnergies 等全球能源股票
代理用 IXC 全球能源 ETF
不直接用 WTI/Brent 原油
```

#### 商品、黄金、原油 FOF

先看原始公告里的基金投资明细，再映射到底层商品敞口。

例子：

```text
160719 嘉实黄金
持有 6 只实物黄金 ETF
实时估值映射 XAU 黄金现货
回测用 IAU 日线收盘标记价
```

```text
160723 嘉实原油
原油 ETF/ETC 按目标资产分成 WTI 和 Brent
公告里直接披露的港股能源股继续保留股票行情
```

杠杆产品要折算倍数：

```text
164701 持有 ProShares Ultra Gold
UGL 按 2x 黄金敞口折算
```

#### FOF / 基金投资明细

如果公告披露的是一篮子 ETF/UCITS 基金：

1. 能直接取价的 ETF 保留对应 ETF 代理。
2. 境外 UCITS、日股、港股 ETF 如果行情源或汇率链路暂不完整，可映射到同类美股 ETF 或指数。
3. 映射必须写入 `rationale`。

例子：

```text
164824 工银印度
EPI、INDA、SMIN、INDY、INCO、GLIN 直接取 Yahoo 行情
UCITS/Amundi MSCI India 映射 INDA
NEXT FUNDS Nifty 50 映射 NFTY
Core SENSEX India ETF 映射 INDY
```

## 配置写法

### 轻量指数代理

```json
{
  "proxy_secids": ["100.HSI"],
  "proxy_basis": "stock_gap",
  "manual_holdings_mode": "proxy_only"
}
```

适合先跑通标准指数型基金。后续如果回测误差大，再查公告升级。

### 公告核验后的手工持仓

```json
{
  "manual_holdings_mode": "replace",
  "manual_holdings": [
    {
      "report_date": "2026-03-31",
      "publish_date": "2026-04-22",
      "rationale": "原始季报 5.9 披露 6 只实物黄金 ETF，合计占基金资产净值 94.94%。",
      "holdings": [
        {
          "secid": "122.XAU",
          "symbol": "XAU",
          "name": "黄金现货等效代理",
          "weight": 0.9494,
          "source": "lookthrough_commodity"
        }
      ]
    }
  ]
}
```

### source 标记

常用标记：

| source | 使用场景 |
|---|---|
| `announcement_stock` | 原始公告股票 |
| `announcement_index_proxy` | 原始公告核验后映射行业/指数代理 |
| `announcement_fund_proxy` | 原始公告基金明细映射可取价 ETF/指数 |
| `lookthrough_commodity` | ETF/ETC/基金穿透成商品敞口 |
| `lookthrough_stock` | ETF/基金穿透成股票 |
| `index_proxy` | 明确跟踪指数 |
| `proxy` | 尚未完全核验的规则化代理 |

## 行情源和 secid

东方财富 `secid` 常见格式：

| 类型 | 示例 |
|---|---|
| 深市 LOF | `0.160924` |
| 沪市 LOF | `1.501301` |
| 港股 | `116.00883` |
| 港股指数代理 | `100.HSI`、`100.HSCEI` |
| 美股/Yahoo 代理 | `107.INDA`、`107.IXC` |
| 黄金现货代理 | `122.XAU` |
| WTI 原油代理 | `102.CL00Y` |
| Brent 原油代理 | `112.B00Y` |

如果新增 `107.*` 这类 Yahoo 代理，需要在 `app/config.py` 的 `YAHOO_PRICE_SYMBOLS` 增加映射：

```python
YAHOO_PRICE_SYMBOLS = {
    "107.INDA": "INDA",
}
```

如果商品/黄金回测需要用 Yahoo 日线收盘标记价，需要在 `US_EQUITY_CLOSE_MARKS` 增加映射：

```python
US_EQUITY_CLOSE_MARKS = {
    "122.XAU": "IAU",
}
```

注意：修改标记价来源后，可能需要清旧 `mark_prices`，否则新旧价格尺度混在一起。
`mark_prices` 只服务回测口径。实时估值如果要从最新净值日推进到当前价，基准价必须与实时行情同一 `secid`、同一价格尺度；不要用 IAU、USO 等 Yahoo 标记价作为 `122.XAU`、`102.CL00Y` 等连续行情的实时基准价。

实时估值跨过最新净值日时，如果缺少同一 `secid` 的净值日基准价，不要用实时行情的单日 `pct` 兜底。该资产应进入 `missing_quotes`，并通过数据警报显示“实时资产收益无法计算”。只有在没有最新净值日期，或无法判断行情日期时，才允许使用 `pct` 或 `price / previous_close - 1` 作为降级估算，并需要查看 `realtime_warnings` 确认降级原因。

## 汇率处理

系统按人民币中间价处理外币资产：

| 资产 | 汇率 |
|---|---|
| 港股、港股指数 | `120.HKDCNYC` |
| 美股、美股 ETF、美元商品 | `120.USDCNYC` |
| A股、人民币资产 | 不转换 |

收益合成：

```text
人民币收益 = (1 + 资产本币收益) * (1 + 汇率收益) - 1
```

如果新增市场，例如 JPY、EUR、INR，需要先确认：

1. 实时汇率源。
2. 历史日线源。
3. `FX_MIDPOINT_SECIDS` 或 override 映射。
4. 回测是否能稳定取到同一口径汇率。

实时汇率缺失或无法计算时，系统会按汇率收益 0 处理并写入 `realtime_warnings`。导入或维护新市场时，如果页面出现“实时估值降级：汇率 ...”警报，应优先补齐实时汇率源和历史日线源，而不是忽略该提示。

## 回测判断

单只导入后看：

```text
MAE
误差标准差
最大绝对误差
最新误差
平均覆盖权重
最大误差日期
```

粗略阈值：

| 质量 | 参考条件 |
|---|---|
| A | MAE <= 0.35%，最大误差 <= 1.2% |
| B | MAE <= 0.60%，最大误差 <= 2.0% |
| C | MAE <= 1.00%，最大误差 <= 3.5% |
| D | MAE > 1.00% 或误差结构不稳定 |

不要只追求 MAE 最小。错误权重或错误代理可能因为误差抵消得到更低 MAE。优先选择原始公告可追溯、经济暴露合理、误差可解释的规则。

## 导入后收尾检查

每批导入并回测后，提交前必须补齐和抽查这些缓存与展示项：

1. 刷新申购限额：执行 `refresh_purchase_limits(con)`，确认 `fund_purchase_limits` 中新增基金有记录。
2. 刷新基金自身场内历史日线：导入返回的 `secids` 必须包含 `exchange_market.code`，并执行 `refresh_daily_prices(con, sorted(secids))`。回测详情页的历史场内价格和折溢价依赖这一步。
3. 刷新实时行情：执行 `refresh_quotes(con, sorted(secids))`，确认列表页场内价格、代理资产价格和折溢价不是旧值。
4. 检查代理资产名称：打开 `/api/funds/{code}/holdings` 或网站详情页，确认资产/代理列显示可读名称，不应只显示裸代码。若是新增代理指数，补 `proxy_name()` 映射。
5. 检查回测详情：打开 `/api/funds/{code}/backtest` 或网站详情页，确认 `trade_close` 和 `close_premium` 已补齐。无成交日可以为空，但有成交日应显示历史场内收盘价和折溢价。
6. 检查无成交处理：如果基金场内实时价或历史收盘价为 `0`，只表示当日无成交；iNAV 仍可纳入，但场内价格和折溢价应显示为空，并在 `note` 或最终报告中说明。
7. 重启 `serve.py` 后抽测 `/api/funds`、`/api/funds/{code}/holdings`、`/api/funds/{code}/backtest`。

## 常见问题

### 平台持仓为空或很低

处理：

1. 不要直接认为剩余仓位是现金。
2. 查原始季报的资产组合和基金投资明细。
3. QDII、FOF、ETF 联接尤其容易出现平台结构化持仓缺失。

例子：

```text
164824 平台结构化持仓缺失，但原始季报披露 10 只印度 ETF/UCITS 基金。
```

### 场内价格为空

处理：

1. 确认基金是否真是 LOF。
2. 检查 `exchange_market` 是否正确。
3. 尝试请求 `0.<code>` 和 `1.<code>`。
4. 如果实时价或历史收盘价返回 `0`，先确认是否为当日无成交。无成交不影响 iNAV 估算，但场内价格和折溢价必须显示为空。
5. 如果长期没有任何场内行情，不能进入主列表。

### 回测某天误差特别大

排查顺序：

1. 是否为分红除息日。回测实际值应为 `单位净值 + 每份现金分红`。
2. 使用的持仓是否在当日已经公告。
3. 资产价格时点是否和净值估算时点一致。
4. 商品期货是否误用了日结算价。
5. 汇率是否缺失或使用了错误币种。
6. 当天是否有大额申购赎回或应收款导致仓位变化。

### 覆盖权重突然变化

处理：

1. 查对应季度原始公告的资产组合。
2. 看是否出现大额应收申购款、现金、债券。
3. 不要机械填满到 100%。未覆盖现金/应收款默认 0 波动。

例子：

```text
160719 2025Q4 原始季报黄金 ETF 合计约 82.98%，其他资产中应收申购款较大。
这部分不应强行填成黄金敞口。
```

### ETF 价格滞后

处理：

1. 实时估值优先用连续交易的底层资产或指数。
2. 回测可用 Yahoo 日线收盘标记价校准时点。
3. ETF 场内成交价只适合作为折溢价观察，不作为底层净值代理首选。
4. 如果实时估值突然出现几十倍偏移，优先检查是否混用了实时行情价格和回测标记价。

### 新增 Yahoo 代理后没有行情

处理：

1. 先用 Yahoo chart 接口测试 symbol 是否有日线。
2. 在 `YAHOO_PRICE_SYMBOLS` 添加 `secid -> symbol`。
3. 重跑 `python import_fund.py <code>`。
4. 检查 `missing_quotes` 是否为空。

### 修改配置后网站没变

处理：

1. 重跑 `python import_fund.py <code>`，更新数据库。
2. 重启 `python serve.py`，因为配置在模块导入时加载。
3. 强制刷新浏览器页面。

### 代理指数代码前缀错位

经验：

1. 不要只看后三位或简称。A 股指数常见同一后三位同时存在 `399xxx` 和 `000xxx`，但可能完全不是同一个指数。
2. 配置 `proxy_secids` 后，必须立即查实时行情返回的 `quote_name`，确认它和基金跟踪指数一致。
3. 本地 `proxy_name()` 只是显示名，不代表行情源真的取到了同一个标的。若显示名和行情返回名冲突，以行情返回名暴露的问题为准。
4. 同一代码有深市/沪市双发布时，要确认二者返回名称是否一致；若不一致，优先使用基金公告、招募说明书或指数公司披露的完整指数代码。
5. 代理修正后重跑单只导入，并检查数据库最新持仓是否从旧 `secid` 切到新 `secid`。
6. 回测为 0 或覆盖仓位异常时，继续检查日线源；“代理方向正确”和“历史行情可回测”是两件事。

典型案例：

```text
163118 申万菱信中证申万医药生物指数 LOF
错误代理：0.399808，行情返回 中证新能
正确代理：1.000808，指数为 中证申万医药生物指数
后续风险：当前 000808 近日日线源需要继续补稳定来源，否则回测 count 可能为 0。
```

批量检查命令：

```powershell
python scripts/audit_proxy_secids.py --cn-index-only
python scripts/audit_proxy_secids.py
python scripts/audit_proxy_secids.py --codes 163118 --check-daily --suggest-alt
python scripts/audit_proxy_secids.py --include-manual
```

检查输出中重点看：

| status | 含义 | 处理 |
|---|---|---|
| `NAME_MISMATCH` | 配置显示名和行情返回名没有有效重合 | 先核对基金跟踪指数，再改 `proxy_secids` 或显示名 |
| `MISSING_QUOTE` | 实时行情没有返回该代理 | 检查 secid、行情源分支或是否需要 Yahoo/专用指数接口 |
| `DAILY_MISSING` | 实时可取但近日日线缺失 | 补日线源，否则回测不可用或覆盖仓位偏低 |
| `OK` | 名称基本一致 | 仍需结合原始公告和回测误差判断是否接受 |

## 建议的 agent 输出

每导入一只基金，最终回复应包含：

```text
基金代码和名称
是否确认有场内价格
查过哪些原始公告
公告中关键资产配置和持仓
导入模式
采用的代理规则
写入了哪些配置
回测 MAE、标准差、最大误差、最新误差
是否建议纳入网站列表
剩余风险或后续可改进点
```

`导入模式` 必须逐只说明，不能只给批量总述。建议使用下面这些固定口径：

| 导入模式 | 说明 | 不确定性 |
|---|---|---|
| `指数型-跟踪指数` | 指数型 LOF 直接使用跟踪指数 | 较低，主要风险是指数行情口径 |
| `ETF联接-目标ETF跟踪指数` | 联接基金穿到目标 ETF，再使用目标 ETF 跟踪指数 | 较低到中等，取决于目标 ETF 仓位和现金比例 |
| `披露持仓直用` | 披露持仓覆盖接近股票占净比，直接使用披露持仓 | 中等，取决于披露滞后 |
| `披露持仓+业绩基准补缺口` | 前十大覆盖不足，用业绩比较基准指数补足股票仓位缺口 | 较高，必须说明缺口权重、补足指数和真实持仓偏离风险 |
| `公告穿透` | FOF、商品、QDII 等按原始公告穿透底层基金/商品/指数 | 中等到较高，取决于公告明细和映射质量 |

同一批里若多只基金属于简单且无争议的同类模式，可以合并说明，例如“160706、161811、165309 均为沪深300指数型，导入模式均为 `指数型-跟踪指数`，代理均使用沪深300指数”。但只要使用缺口补足、公告穿透、目标 ETF 核验或其他不确定性更高的规则，就必须逐只展开说明。

如果使用 `披露持仓+业绩基准补缺口`，最终回复必须额外写清：

```text
股票占净比
已披露持仓权重
缺口权重
使用的业绩基准指数及 secid
为什么不用主观风格指数
```

如果没能完成，应明确卡在哪一步，例如：

```text
没有找到原始 PDF
有 PDF 但无法抽表
行情源缺失
确认不是 LOF
回测误差过大，暂不建议纳入
```
